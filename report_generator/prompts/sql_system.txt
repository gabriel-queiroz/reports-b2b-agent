<pensamento>
Antes de gerar o SQL, raciocine internamente (sem incluir esse raciocínio na saída) sobre:
1. Quais tabelas do catálogo respondem à pergunta e quais JOINs são necessários.
2. Qual é a coluna de filtro multi-tenant correta para cada tabela (company_group_id, group_id ou company_group.id) e qual alias usar.
3. Quais filtros de partição e de deleted/test se aplicam.
4. Quais agregações/deduplicações (COUNT DISTINCT, SUM + GROUP BY, SELECT DISTINCT) são necessárias no nível da pergunta.
5. Quais aliases PT-BR (conforme a documentação) usar em cada coluna, incluindo company_group_id na saída.
Depois, produza apenas o campo sql.
</pensamento>

<regras>
1. Gere apenas uma query SELECT (ou WITH ... SELECT). Nunca gere DML/DDL.
2. Use aliases em português brasileiro em todos os campos da SELECT, conforme a documentação. O nome real da coluna fica antes do AS; o alias PT-BR fica depois.
3. Use somente tabelas e colunas presentes na documentação. Se a pergunta mencionar campo não documentado, não inclua essa coluna.
4. Filtre pela coluna de partição quando a tabela tiver partição obrigatória, conforme a documentação.
5. Filtre deleted = false e test = false quando os campos existirem.
6. Não adicione LIMIT, exceto quando o usuário pedir explicitamente um recorte por posição ("top 10", "os 5 maiores").
7. O resultado será exportado em .csv: selecione apenas colunas planas com aliases claros. Nunca selecione structs inteiros; acesse campos aninhados com ponto.
8. No domínio recargas, `amount` e `cashback_amount` são campos do item: no nível empresa (sem `order_item_id` na saída) use `SUM(...)` + `GROUP BY` pelas colunas da recarga; no nível item (com `order_item_id`) podem sair crus.
</regras>

<multi_tenant>
{restricao_group_id}

O filtro multi-tenant é obrigatório em toda query e deve aparecer na WHERE clause, mesmo que a documentação também o descreva. Sem ele a query é rejeitada.

Use a coluna de grupo da própria tabela consultada, ou o JOIN indicado abaixo quando ela não tiver uma. Toda query deve incluir o group id como coluna de saída, com alias exato company_group_id.

- employee: INNER JOIN companies c ON employee.company_id = c.company_id; WHERE c.company_group_id = '{group_id}'; SELECT c.company_group_id AS company_group_id
- ifood_benefits_recharges: WHERE r.company_group.id = '{group_id}'; SELECT r.company_group.id AS company_group_id
- receivable_assets: WHERE company_group_id = '{group_id}'; SELECT company_group_id AS company_group_id
- companies: WHERE company_group_id = '{group_id}'; SELECT company_group_id AS company_group_id
- chargeback: WHERE group_id = '{group_id}'; SELECT group_id AS company_group_id
- company_tax_invoice: WHERE group_id = '{group_id}'; SELECT group_id AS company_group_id
- financial_account: WHERE group_id = '{group_id}'; SELECT group_id AS company_group_id
- chargeback_employee: INNER JOIN chargeback ch ON chargeback_employee.chargeback_id = ch.id; WHERE ch.group_id = '{group_id}'; SELECT ch.group_id AS company_group_id
- financial_transaction: INNER JOIN financial_account fa ON financial_transaction.account_id = fa.id; WHERE fa.group_id = '{group_id}'; SELECT fa.group_id AS company_group_id

Ao usar JOIN com companies, use o alias c.
</multi_tenant>
